# RODiT SDK security audit

**Date:** 15 November 2026  
**Scope:** this monorepo, four published npm packages  
**Method:** [CodeCome](https://github.com/discernible-io/CodeCome-Recommended) reconnaissance, hypothesis review, counter-analysis, and sandbox checks. Exploit development was not run.

The review covered authentication, authorization, webhook verification, HOLA signing and verification, JWT handling, and cryptographic use. Findings below are the ones filed. Maintainer review closed the design questions. One code defect was fixed.

## Remediation

| ID | Package | Topic | Status |
|----|---------|--------|--------|
| CC-0001 | `@rodit/rodit-auth-be` | `RoditClient.isOperationPermitted` returns true when the permission matrix is missing, the path is not listed, or the check throws | **By design.** This is a local filter inside `request()`. It blocks only an explicit grant that does not start with `+`. `authorize` (`validatepermissions`), after `authenticate`, is the allow/deny for an incoming request. |
| CC-0002 | `@rodit/rodit-auth-be` | `validatepermissions` reads JWT claims with `decodeJwt` and does not verify the signature | **By design.** `authenticate` verifies the signature and session. `authorize` maps claims onto the route. The two middlewares are mounted in that order. |
| CC-0003 | `@rodit/rodit-auth-be` | Webhook signature and session checks relax when `NODE_ENV` is `test` | **By design.** The test profile exists so webhook handlers can run without a live signer session. `NODE_ENV=main` still requires the session. |
| CC-0004 | `@rodit/rodit-auth-be` | Permission keys containing `*` were compiled as an unanchored regular expression | **Fixed in 10.0.4.** A `*` key is now an anchored glob: every `*` matches any sequence, and every other character is literal. |

Static analysis also reported polynomial regular expressions in `@rodit/hola-client` (`lib/generate-near-account.js`, `lib/nonce-api.js`) and in `rodit-auth-be/lib/middleware/webhookhandlermw.js`. Those were not confirmed as defects and no package version changed for them.

## What 10.0.4 changes for integrators

Upgrade `@rodit/rodit-auth-be` to **10.0.4** to pick up the glob matcher. Route protection is unchanged: `authenticate`, then `authorize`. `isOperationPermitted` remains the client pre-check used by `request()`. Webhook tests still use `NODE_ENV=test`.
